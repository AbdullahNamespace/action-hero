# 08 — Concurrency والمهلات

> الملف: [`08-concurrency.yml`](../.github/workflows/08-concurrency.yml)

**الهدف:** عدم إهدار الدقائق على تشغيلات قديمة، ومنع التشغيلات المتعارضة، وإيقاف الـ jobs العالقة.

## `concurrency`

التشغيلات التي تشترك في **group** واحد لا تعمل في آن واحد.

```yaml
concurrency:
  group: demo-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true
```

| الإعداد                     | السلوك                                               |
| --------------------------- | ---------------------------------------------------- |
| `cancel-in-progress: true`  | التشغيل الجديد **يلغي** الجاري                       |
| `cancel-in-progress: false` | التشغيل الجديد **ينتظر**؛ ويبقى أحدث تشغيل منتظر فقط |

أسماء المجموعات تعبيرات — مجموعة لكل فرع / PR / بيئة.

| الاستخدام                 | الإعداد | السبب                   |
| ------------------------- | ------- | ----------------------- |
| CI والاختبارات والمعاينات | `true`  | يهمّ آخر commit فقط     |
| **النشر**                 | `false` | لا نقطع نشرًا في منتصفه |

يعمل على مستوى الـ workflow (التشغيل كله) أو الـ job (هذا الـ job فقط — انظر job `queued`).

## المهلات

```yaml
jobs:
  slow:
    timeout-minutes: 5 # الـ job كله (الافتراضي 360!)
    steps:
      - timeout-minutes: 1 # خطوة واحدة
        run: sleep 120
```

الـ job المنتهي مهلته يُعلَّم فاشلًا ويُلغى. ضع مهلة لكل job: الافتراضي 6 ساعات من الدقائق المحتسبة.

## فخاخ شائعة

- `cancel-in-progress: true` على النشر ← نشر ناقص ([الخطأ 14](mistakes-log.ar.md)).
- group واسع جدًا (نص ثابت) يجعل تشغيلات غير مترابطة تلغي بعضها.
- التشغيلات الملغاة تتخطى الخطوات العادية؛ استخدم `if: always()` / `cancelled()` للتنظيف.

## تمرين

ادفع commitين إلى `main` بسرعة وراقب إلغاء التشغيل الأول. ثم شغّله يدويًا بـ `hang=true` وراقب مهلة الخطوة بعد دقيقة.
